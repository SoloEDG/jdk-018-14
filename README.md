# GLYPH ASCII Studio

安装：`npm ci`

本地启动：`npm run dev`

Docker 启动：`docker compose up --build`，访问 http://localhost:18018。

测试：`npm run test`（边界求交与误差扩散的单元测试）

## 误差扩散与传播边界

默认是逐格直接映射；在「04 / DIFFUSION」开启**误差扩散**后，量化误差按
Floyd–Steinberg（蛇形扫描）在字符单元间传播，减少天空等渐变区域的色带。

- **屏障线**：在原图上拖出的直线，误差不得跨越。适合框住细字、轮廓边缘，
  防止高亮区域的误差被推入文字。
- **保护区**：框选的矩形区域，区内保持原来的直接映射，误差不进不出。
- **连续 / 分区对比**：打开对比开关后，同一次生成任务产出两种变体，
  预览中可原地切换并并列查看颗粒感（相邻单元平均亮度差）与斑点数；
  字符画布与纯文本始终读取同一个 `grid.cells`，来自同一次传播任务。

### 边界求交规则（可解释的取舍）

边界以**原图归一化坐标**保存，与裁剪、字符密度无关；每次生成时依据当前
裁剪与密度**重新求交**（连续浮点坐标，不做四舍五入）：

1. 线段与单元网格线的交点封锁对应单元边；
2. 线端点落在单元内部（线只穿过半个单元）时，该单元**整格隔离**——
   宁可多挡一格，也不把端点吸附到网格线上、更不漏挡；
3. 完全位于某单元内部的短线同样隔离该单元，不会被静默丢弃；
4. 恰好压在网格线上的线段，封锁它沿途覆盖的所有单元边；
5. 完全落在裁剪区外的边界不参与生成，但会在面板中计数列明；
6. 保护区按「碰到即保护」处理，最多向外多保护不到一格。

被截断的误差在边界处**丢弃**（不绕行、不跨越），总量计入面板统计。
点击预览中的任意单元，可查看该单元的误差来源（方向 / 权重 / 数值）、
去向，以及每条传播被截断的原因（屏障线编号 / 保护区 / 网格边缘）。

预览中的边界覆盖层绘制在独立画布上，**不会进入导出的 PNG 或文本**。
生成管线为异步任务模型：快速调整伽马等参数时，旧任务的结果会被丢弃，
不会覆盖新结果。
